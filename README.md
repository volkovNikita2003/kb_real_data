# Автоматическая обработка реальных данных

`real_data_auto` — проект обработки экспериментальных данных дифракционного
анализатора размера частиц.

Цель проекта — запускать калибровку, прямое численное моделирование и
восстановление распределения частиц без редактирования исходного кода. Каждый
этап получает путь к директории эксперимента, читает данные и параметры из
заранее определённых мест и сохраняет воспроизводимый результат в `output/`.

## Термины

### Эксперимент

Эксперимент объединяет измерения, для которых одинаковы:

- параметры оптической схемы;
- положения и характеристики детекторов;
- длина волны;
- оптические свойства частиц и среды;
- калибровка;
- аппаратная матрица.

Ответственность за выполнение этих условий несёт пользователь.

### Измерение

Измерение — один набор зарегистрированных сигналов конкретного образца внутри
эксперимента. Один эксперимент может содержать несколько измерений, например
`kmk_15`, `kmk_100` и `kmk_270`.

### Профиль восстановления

Профиль восстановления — именованный набор параметров решения обратной задачи.
Для одного измерения можно выполнить восстановление с несколькими профилями,
например `default`, `camera_only` или `strong_regularization`.

В общем случае восстановление выполняется для пар:

```text
профиль восстановления × измерение
```

## Структура эксперимента

В корне эксперимента допускаются только:

```text
data/
input_parameters/
output/              # необязательная директория результатов
```

Для открытия эксперимента обязательны только `data/` и `input_parameters/`.
Директория `output/` создаётся скриптом обработки при сохранении первого
результата. Если `output` уже существует, он должен быть директорией.

Названия экспериментов, измерений и профилей должны иметь безопасный формат:

```text
^[A-Za-z0-9][A-Za-z0-9_-]*$
```

Это исключает пробелы, служебные символы и неоднозначность при построении путей.

### `data/`

Каталог содержит:

- специальную директорию `calibration`;
- одну или несколько директорий измерений.

Других файлов и директорий непосредственно в `data/` быть не должно.

### `input_parameters/`

Содержит только входные параметры, заданные пользователем:

- `general.yaml` — общие параметры эксперимента и оптической схемы;
- `calibration.yaml` — параметры калибровки;
- `darl.yaml` — параметры прямого численного моделирования;
- `restore_profiles/*.yaml` — профили восстановления.

### `output/`

Содержит только результаты автоматической обработки:

- `calibration/` — калибровка;
- `darl/` — аппаратная матрица и результаты моделирования;
- `restore/` — результаты восстановления;
- `archive/` — предыдущие версии результатов после запуска с `--force`.

Исходные данные и входные параметры скрипты не изменяют.

## Калибровочные данные

```text
data/calibration/
├── cam/
│   ├── 100.bmp
│   ├── 500.bmp
│   └── 2500.bmp
└── lin/
    └── 15.txt
```

Наличие `cam/` и `lin/` определяется включёнными детекторами из
`general.yaml`.

В `cam/` находятся изображения сигнала калибровочного пинхола. В `lin/`
находится ровно один файл сигнала линейки. Параметры калибровки хранятся
в `calibration.yaml`.

Если данные выключенного детектора присутствуют, валидатор выдаёт
предупреждение. Если данные включённого детектора отсутствуют — ошибку.

## Данные измерения

Полная структура измерения с камерой, линейкой и фоном:

```text
data/<имя измерения>/
├── cam/
├── cam_back/
├── lin/
└── lin_back/
```

Назначение директорий:

- `cam/` — сигнал камеры;
- `cam_back/` — фон камеры;
- `lin/` — сигнал линейки;
- `lin_back/` — фон линейки.

Наличие `cam/` и `lin/` определяется включёнными детекторами. Необходимость
`cam_back/` и `lin_back/` определяется выбранным профилем восстановления.

Правила проверки:

| Данные требуются | Директория существует | Результат |
|---|---:|---|
| да | да | норма |
| да | нет | ошибка |
| нет | да | предупреждение |
| нет | нет | норма |

Так как разные профили могут использовать разные детекторы и фон, полная
проверка выполняется отдельно для каждой пары «профиль × измерение».

## Имена файлов и экспозиции

Время экспозиции задаётся положительным целым числом в микросекундах.

Для камеры:

```text
<экспозиция>.bmp
```

Для линейки:

```text
<экспозиция>.txt
```

Допустимые примеры:

```text
24.bmp
400000.bmp
10.txt
```

Недопустимые примеры:

```text
0.bmp
-24.bmp
24.5.bmp
24us.bmp
024.bmp
```

Экспозиция должна:

- состоять только из ASCII-цифр;
- быть строго больше нуля;
- не содержать ведущих нулей.

Позднее возможна добавка дробных экспозиций.

### Камера и фон

Если профиль использует фон камеры, каждой сигнальной экспозиции должна
соответствовать такая же фоновая экспозиция.

- отсутствие фона для сигнальной экспозиции — ошибка;
- лишняя фоновая экспозиция — предупреждение.

### Линейка и фон

В каждой используемой директории `lin/` и `lin_back/` должен находиться ровно
один TXT-файл. При использовании фона экспозиции сигнала и фона должны
совпадать.

Позднее при необходимости можно будет добавить HDR сборку сигнала с линейки.

## Результаты этапов

### Калибровка

Команда:

```bash
python src/preprocessing.py experiments/<эксперимент>
```

Входы:

```text
data/calibration/
input_parameters/general.yaml
input_parameters/calibration.yaml
```

Результаты:

```text
output/calibration/
├── used-parameters.yaml
├── result.yaml
├── figures/
└── ...
```

`result.yaml` содержит параметры камеры и линейки, вычисленные при
калибровке и необходимые следующим этапам.

### Прямое численное моделирование

Команда:

```bash
python src/calc_darl.py experiments/<эксперимент>
```

Входы:

```text
input_parameters/general.yaml
input_parameters/darl.yaml
output/calibration/result.yaml
```

Результаты:

```text
output/darl/
├── used-parameters.yaml
├── result.yaml
├── matrix.npz
├── camera_bins.txt
├── line_bins.txt
├── particle_classes.txt
└── ...
```

Калибровка и аппаратная матрица общие для всех измерений эксперимента.

### Восстановление

По умолчанию выполняются все профили для всех измерений:

```bash
python src/restore.py experiments/<эксперимент>
```

Все профили для одного измерения:

```bash
python src/restore.py experiments/<эксперимент> \
  --measurement kmk_15
```

Один профиль для всех измерений:

```bash
python src/restore.py experiments/<эксперимент> \
  --profile default
```

Одна конкретная пара:

```bash
python src/restore.py experiments/<эксперимент> \
  --profile default \
  --measurement kmk_15
```

Структура результатов:

```text
output/restore/
└── <профиль>/
    └── <измерение>/
        ├── used-parameters.yaml
        ├── result.yaml
        ├── restored-distribution.txt
        ├── reconstructed-signal.txt
        ├── figures/
        └── ...
```

В `used-parameters.yaml` сохраняется полный фактический набор параметров
конкретной пары «профиль × измерение». Он включает:

- общие параметры эксперимента;
- профиль восстановления;
- результаты калибровки;
- сведения об аппаратной матрице;
- детекторы, пути и экспозиции конкретного измерения;
- значения по умолчанию.

### Полная обработка

Команда:

```bash
python src/run.py experiments/<эксперимент>
```

Последовательность:

```text
валидация
→ калибровка
→ численное моделирование
→ восстановление всех пар
```

Следующий этап не запускается, если предыдущий завершился ошибкой.

## Повторный запуск

Существующие результаты не перезаписываются автоматически. Если целевой каталог
уже существует, скрипт завершает работу с сообщением об ошибке.

Для повторного расчёта используется:

```bash
python src/<скрипт>.py experiments/<эксперимент> --force
```

Перед новым расчётом старая версия целиком переносится в `output/archive/` с
временной меткой, например:

```text
output/archive/calibration_2026-07-24T12-30-45/
output/archive/darl_2026-07-24T13-10-20/
output/archive/restore_default_kmk_15_2026-07-24T14-05-17/
```

Для восстановления архивируется только заменяемая пара «профиль × измерение».
Её `used-parameters.yaml` переносится вместе с остальными результатами.

## Назначение модулей `src/`

- `experiment.py` — единое представление структуры эксперимента и построение
  путей;
- `parameters.py` — чтение, проверка и объединение параметров;
- `validate.py` — проверка структуры, файлов и параметров;
- `output.py` — создание результатов, защита от перезаписи и архивирование;
- `errors.py` — общие типы ошибок;
- `preprocessing.py` — калибровка;
- `calc_darl.py` — прямое моделирование и аппаратная матрица;
- `restore.py` — восстановление распределений;
- `run.py` — последовательный запуск всего процесса.

## Модель эксперимента

Модуль `experiment.py` реализует классы `Experiment`, `Measurement` и
`RestoreProfile`. Он не читает сигналы и не выполняет вычисления.

Открытие эксперимента:

```python
from experiment import Experiment

experiment = Experiment.open("experiments/17_07_26_kmk_15")
```

При открытии проверяются:

- существование директории эксперимента;
- безопасное имя эксперимента;
- наличие `data/` и `input_parameters/`;
- корректность необязательной директории `output/`;
- отсутствие посторонних элементов в корне;
- наличие `data/calibration/`;
- отсутствие файлов непосредственно в `data/`;
- безопасные имена измерений.

Получение измерений:

```python
experiment.measurement_names()
experiment.measurements()

measurement = experiment.measurement("kmk_15")
measurement.camera_dir
measurement.camera_background_dir
measurement.line_dir
measurement.line_background_dir
```

Получение профилей восстановления:

```python
experiment.restore_profile_names()
experiment.restore_profiles()
experiment.restore_profile("default")
```

Если `input_parameters/restore_profiles/` ещё не создан, эксперимент содержит
пустой набор профилей. Если директория существует, в ней разрешены только
YAML-файлы с безопасными именами.

Стандартные пути результатов строятся без создания директорий:

```python
experiment.calibration_output_dir
experiment.darl_output_dir
experiment.archive_dir
experiment.restore_output_dir("default", "kmk_15")
```

Для построения пути результата восстановления указанные профиль и измерение
должны существовать. Это позволяет обнаруживать опечатки до запуска обработки.

Модульные тесты запускаются из корня проекта:

```bash
python -m unittest discover -s tests -v
```

Варианты внутренней реализации модели и условия совместимого рефакторинга
описаны в [docs/experiment-model.md](docs/experiment-model.md).

## Подготовленные эксперименты

В проект добавлены три набора данных для разработки и проверки:

| Эксперимент | Измерения | Детекторы |
|---|---|---|
| `17_07_26_kmk_15` | `kmk_15` | камера и линейка |
| `16_07_26` | `kmk_100`, `kmk_160`, `kmk_270` | только камера |
| `07_07_26` | `kmk_15`, `kmk_100`, `kmk_270` | камера и линейка |

Они позволят проверить:

- эксперимент с одним и несколькими измерениями;
- опциональное использование линейки;
- пакетное восстановление;
- несколько сочетаний профилей и измерений.

## Состояние реализации

В локальной директории experiments/ подготовлены три эксперимента для разработки и проверки. Каталог исключён из Git.

Директории `input_parameters/` предназначены для YAML-файлов параметров.
Директории `output/` предназначены только для файлов, создаваемых скриптами
обработки, и также исключены из Git.

Реализованы:

- модель структуры эксперимента в `experiment.py`;
- общая ошибка структуры эксперимента в `errors.py`;
- модульные тесты модели эксперимента.

Следующие модули реализуются в таком порядке:

1. загрузка и проверка параметров в `parameters.py`;
2. валидатор данных и параметров в `validate.py`;
3. калибровка в `preprocessing.py`;
4. численное моделирование в `calc_darl.py`;
5. восстановление в `restore.py`;
6. архивирование результатов в `output.py`;
7. полный запуск обработки в `run.py`.
8. подготовка примеров данных для git
