# Руководство пользователя

Это руководство предназначено для пользователя, который понимает физический
смысл калибровки, прямого моделирования и восстановления распределения частиц,
но не обязан знать устройство Python-кода проекта.

Программа выполняет три последовательных этапа:

1. калибровку камеры и линейки;
2. расчёт аппаратной матрицы и модельных сигналов DARL;
3. восстановление распределения частиц по реальным сигналам.

Все исходные данные и пользовательские параметры находятся внутри каталога
эксперимента. Результаты создаются автоматически в его каталоге `output/`.
Редактировать исходный код для обработки нового эксперимента не требуется.

## 1. Основные понятия

**Эксперимент** объединяет измерения с одной оптической схемой, положением и
характеристиками детекторов, длиной волны, свойствами частиц и среды. Для всех
его измерений используются общие калибровка и аппаратная матрица. Пользователь
отвечает за то, что объединённые в эксперимент измерения действительно
совместимы.

**Измерение** — сигналы одного образца. В эксперименте может быть любое число
измерений.

**Профиль восстановления** — именованный набор настроек обратной задачи. Одно
измерение можно обработать несколькими профилями, не копируя исходные данные.

## 2. Быстрый запуск

Команды следует выполнять из корня проекта `real_data_auto`. После установки
зависимостей полный расчёт запускается так:

```bash
python src/run.py all experiments/<имя_эксперимента>
```

Перед длительным расчётом рекомендуется проверить входные данные:

```bash
python src/validate.py experiments/<имя_эксперимента>
```

Отдельные этапы запускаются через тот же интерфейс:

```bash
python src/run.py calibration experiments/<имя_эксперимента>
python src/run.py darl experiments/<имя_эксперимента>
python src/run.py restore experiments/<имя_эксперимента>
```

Команды должны выполняться в указанном порядке. DARL использует результат
калибровки, а восстановление — результаты калибровки и DARL.

## 3. Подготовка эксперимента

Каталог эксперимента должен иметь следующую структуру:

```text
experiments/<имя_эксперимента>/
├── data/
│   ├── calibration/
│   │   ├── cam/
│   │   └── lin/
│   ├── <измерение_1>/
│   │   ├── cam/
│   │   ├── cam_back/
│   │   ├── lin/
│   │   └── lin_back/
│   └── <измерение_2>/
├── input_parameters/
│   ├── general.yaml
│   ├── calibration.yaml
│   ├── darl.yaml
│   ├── measurements/
│   │   └── <измерение>.yaml
│   └── restore_profiles/
│       └── <профиль>.yaml
└── output/                 # создаётся программой
```

Имена экспериментов, измерений и профилей должны начинаться с латинской буквы
или цифры и содержать только латинские буквы, цифры, `_` и `-`.

В качестве основы удобно скопировать один из каталогов:

- `examples/minimal/` — только обязательные поля;
- `examples/complete/` — все поддерживаемые поля с пояснениями и допустимыми
  значениями.

В примерах нужно заменить значения на параметры своего прибора и эксперимента.

## 4. Подготовка реальных данных

### Данные калибровки

Для камеры изображения пинхола помещаются в `data/calibration/cam/`. Имя файла
равно времени экспозиции в микросекундах:

```text
100.bmp
500.bmp
1000.bmp
```

Допустимы только положительные целые экспозиции без единиц измерения в имени.
Для линейки в `data/calibration/lin/` должен находиться ровно один файл того же
формата, например `1000.txt`. Пример содержимого файла смотри в примерах 
экспериментов. По сути это скопированные два столбца с номером пикселя и 
сигналом линейки из excel таблицы.

Каталог отсутствующего детектора не нужен. Наличие детектора задаётся в
`general.yaml`, а не определяется автоматически по каталогам.

### Данные измерения

Каждое измерение хранится в отдельном каталоге `data/<измерение>/`.

- `cam/` — изображения сигнала камеры;
- `cam_back/` — изображения фона камеры;
- `lin/` — сигнал линейки;
- `lin_back/` — фон линейки.

Камера может иметь несколько экспозиций для сборки HDR. Если профиль включает
вычитание фона, каждой экспозиции сигнала должен соответствовать файл фона с
тем же именем. Лишние экспозиции фона разрешены, но вызывают предупреждение.

В `lin/` должен быть ровно один TXT-файл. При вычитании фона в `lin_back/`
также должен быть ровно один файл с той же экспозицией.

Если детектор или фон включён параметрами, соответствующий каталог обязателен.
Если каталог присутствует, но не используется, валидатор сообщает
предупреждение.

## 5. Откуда берутся параметры

Параметры разделены по их назначению. Один и тот же физический параметр не
следует дублировать в нескольких файлах.

| Источник | Что в нём задаётся | Откуда пользователь берёт значения |
|---|---|---|
| `general.yaml` | Состав и постоянная геометрия детекторов, номинальные размеры и число пикселей, положение детекторов, длина волны и фокусное расстояние | Паспорт прибора, конструкция оптической схемы и фактически установленное оборудование |
| `calibration.yaml` | Геометрия калибровочного измерения и настройки алгоритма калибровки/HDR | Условия съёмки пинхола и выбранные настройки обработки |
| `darl.yaml` | Оптические свойства частиц и среды, тип частиц, классы размеров, параметры моделируемого сигнала | Свойства образца и материалов, постановка эксперимента и требуемая сетка размеров |
| `measurements/<измерение>.yaml` | Необязательное ожидаемое распределение конкретного образца | Предварительная информация об образце или независимые измерения, например оценки `d10`, `d50`, `d90` |
| `restore_profiles/<профиль>.yaml` | Используемые детекторы и фон, HDR, диапазон классов и параметры решателя | Выбранная методика решения обратной задачи |
| Имена файлов в `data/` | Экспозиции реальных сигналов | Настройки, использованные при регистрации данных |
| `output/calibration/result.yaml` | Вычисленные калибровочные величины | Создаётся программой по пинхолу; вручную не задаётся |
| `output/darl/result.yaml` | Пути и метаданные аппаратной матрицы, классов и бинов | Создаётся программой DARL; является входным контрактом восстановления |

Полный перечень полей и комментарии к каждому из них приведены в
`examples/complete/input_parameters/`. Файлы YAML не поддерживают Python-выражения:
нужно записывать готовые числовые значения. Числа должны быть конечными —
`NaN` и бесконечности отклоняются.

### `general.yaml`

Секция детектора означает, что детектор физически присутствовал и должен
участвовать в соответствующих этапах. Если секции `camera` или `line_sensor`
нет, детектор считается отсутствующим. Здесь указываются именно постоянные
характеристики оборудования, а не результат его калибровки.

### `calibration.yaml`

Сейчас поддерживается только `mode: automatic`. Для линейки обязательно
задаются положения пинхола и сигнала в метрах. Настройки HDR относятся к
объединению калибровочных кадров камеры. Состав секций детекторов должен
соответствовать `general.yaml`.

Калибровочные смещения, эффективные размеры пикселей и коэффициент перевода
сигнала линейки программа вычисляет сама. Поддерживаемого режима ручной замены
этих результатов пока нет; редактировать файлы в `output/` не рекомендуется.

### `darl.yaml`

Здесь находятся физические входы прямой модели: коэффициенты преломления и
поглощения частиц, тип частиц, коэффициенты преломления среды и кюветы, а также
сетка классов размеров. Параметры геометрии детекторов берутся из
`general.yaml`, а уточнённые калибровочные величины — из
`output/calibration/result.yaml`.

### Ожидаемое распределение измерения

Файл `input_parameters/measurements/<измерение>.yaml` необязателен. Он описывает
предполагаемое распределение именно этого образца. DARL рассчитывает по нему
ожидаемый сигнал, чтобы затем сравнить его с реальным.

Этот файл не задаёт ограничение для алгоритма восстановления и не сообщает ему
правильный ответ. Если известны только `d10`, `d50`, `d90`, пользователь сам
подбирает параметры поддерживаемого распределения, согласующиеся с этими
оценками. При отсутствии файла расчёт продолжается без такого сравнения.

### Профиль восстановления

Профиль определяет вычислительный вариант восстановления: какие детекторы
использовать, вычитать ли фон, как собирать HDR, какой диапазон классов брать и
с какими параметрами запускать решатель. Профиль может использовать подмножество
детекторов эксперимента. Текущая legacy-реализация требует камеру и поддерживает
варианты «только камера» и «камера с линейкой».

Один профиль применяется ко всем измерениям по умолчанию. Фактическая полная
конфигурация сохраняется отдельно для каждой пары «профиль × измерение».

## 6. Проверка до расчёта

Запустите валидатор:

```bash
python src/validate.py experiments/<имя_эксперимента>
```

Ошибка означает, что расчёт продолжать нельзя. Предупреждение сообщает о
подозрительной, но допустимой ситуации. Для автоматических запусков можно
превратить предупреждения в ошибки или скрыть их:

```bash
python src/validate.py experiments/<имя_эксперимента> --warnings-as-errors
python src/validate.py experiments/<имя_эксперимента> --no-warnings
```

Эти два флага взаимоисключающие. Они также доступны у подкоманд `run.py`.

## 7. Варианты запуска

### Полная обработка

```bash
python src/run.py all experiments/<имя_эксперимента>
```

Команда последовательно выполняет калибровку, DARL и все восстановления. Если
поздний этап завершится ошибкой, успешно созданные результаты предыдущего этапа
останутся на диске: весь процесс не является одной транзакцией.

### Выбор измерений и профилей

По умолчанию восстановление выполняется для всех комбинаций профилей и
измерений. Выбор можно ограничить:

```bash
python src/run.py restore experiments/<имя_эксперимента> \
  --profile default \
  --measurement sample_1
```

Флаги можно повторять:

```bash
python src/run.py restore experiments/<имя_эксперимента> \
  --profile default --profile camera_only \
  --measurement sample_1 --measurement sample_2
```

Те же селекторы принимает команда `all` для своего этапа восстановления.

### Повторный расчёт

Без дополнительных флагов программа не перезаписывает существующий результат.
Для пересчёта используется `--force`:

```bash
python src/run.py darl experiments/<имя_эксперимента> --force
```

Старый результат не удаляется, а переносится в `output/archive/` с отметкой
времени. Архив повторяет структуру `output/`, например:

```text
output/archive/restore/<профиль>/<измерение>/<время>/
```

## 8. Что проверять после каждого этапа

### Калибровка

Результаты находятся в `output/calibration/`. Следует проверить:

- графики исходного и приближённого сигналов камеры и линейки;
- найденные центры, смещения и положения максимумов;
- эффективные размеры пикселей;
- коэффициент перевода единиц линейки в единицы камеры;
- отсутствие явных артефактов HDR и неудачного фита.

`result.yaml` содержит строгий машинно-читаемый результат для следующих
этапов. `used-parameters.yaml` фиксирует фактически применённые параметры.

### DARL

Результаты находятся в `output/darl/`. Следует проверить:

- аппаратную матрицу и соответствие её строк бинам детекторов;
- сетку классов частиц;
- тестовые сигналы и восстановления, предусмотренные legacy-расчётом;
- ожидаемые сигналы измерений, для которых заданы предполагаемые распределения;
- отсутствие ошибок или физически необъяснимых особенностей модельных сигналов.

Если тестовое распределение не восстанавливается даже на модельном сигнале,
реальное восстановление обычно нельзя считать надёжным без изменения сетки,
детекторов или параметров решения.

`output/darl/result.yaml` — полный входной контракт следующего этапа. В нём
записаны используемые детекторы, тип сигнала и пути к матрице, классам, бинам и
ожидаемым сигналам.

### Восстановление

Результат каждой пары находится в:

```text
output/restore/<профиль>/<измерение>/
```

Следует проверить:

- обработанные сигналы и качество вычитания фона/HDR;
- восстановленное распределение и его устойчивость;
- выбранную регуляризацию, GCV и зависимость результата от `alpha`;
- согласие восстановленного модельного сигнала с измеренным;
- сравнение с ожидаемым сигналом, если для измерения задано распределение;
- чувствительность результата к разумным изменениям профиля.

В каталоге сохраняются полный `used-parameters.yaml`, legacy-файл параметров,
строгий `result.yaml`, численные массивы и графики. Благодаря этому результат
можно интерпретировать и архивировать независимо от других восстановлений.

## 9. Какие этапы повторять после изменения входов

| Что изменилось | Что нужно выполнить заново |
|---|---|
| Калибровочные данные или `calibration.yaml` | Калибровку, DARL, восстановление |
| Геометрия/состав прибора в `general.yaml` | Обычно всю цепочку |
| Оптика частиц, среды или классы в `darl.yaml` | DARL и восстановление |
| Ожидаемое распределение измерения | DARL и восстановление этого измерения для обновления сравнения |
| Профиль восстановления | Только восстановление с этим профилем |
| Реальный сигнал или фон измерения | Только восстановление этого измерения |
| Добавлен новый профиль при неизменных калибровке и матрице | Только восстановление |

Для частичного пересчёта запускайте нужные подкоманды последовательно с
`--force`. Команда `all` всегда начинает с калибровки.

## 10. Воспроизводимость и редактирование файлов

Пользователь редактирует только данные в `data/` и YAML-файлы в
`input_parameters/`. Файлы в `output/` создаются программой и не должны
использоваться как место ручной настройки.

Для воспроизводимости конкретного результата необходимо сохранять вместе:

- исходные реальные данные;
- каталог `input_parameters/`;
- соответствующий каталог результата с фактически использованными параметрами;
- версию исходного кода программы.

YAML-файлы проверяются строго: неизвестные поля, неправильные типы, повторные
ключи, нечисловые и бесконечные значения приводят к ошибке. Значения по
умолчанию разворачиваются в `used-parameters.yaml`, поэтому в нём видны не
только явно заданные, но и все реально применённые параметры.

## 11. Типичные проблемы

**Программа сообщает, что результат уже существует.** Добавьте `--force`, если
нужен осознанный пересчёт. Предыдущая версия будет перенесена в архив.

**Нет каталога детектора.** Проверьте согласованность `general.yaml`, профиля и
структуры `data/`. Для включённого детектора каталог обязателен.

**Не совпадают экспозиции сигнала и фона.** Переименуйте файлы по фактическим
экспозициям или добавьте недостающий фон. Для линейки экспозиции должны
совпадать точно.

**Не найден профиль или измерение.** Проверьте безопасное имя и соответствие
имени YAML-файла имени каталога измерения.

**DARL или восстановление не находят предыдущий результат.** Выполните этапы в
порядке `calibration` → `darl` → `restore` либо запустите `run.py all`.

**Нужно понять допустимые значения конкретного поля.** Откройте одноимённый
файл в `examples/complete/input_parameters/`: рядом с каждым полем приведены
его смысл, единицы измерения, ограничения и варианты перечислений.

Справка по любой команде доступна через `--help`, например:

```bash
python src/run.py restore --help
```
