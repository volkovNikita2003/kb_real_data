# Контракт legacy-конфигурации DARL

Документ фиксирует происхождение каждого рабочего поля эталонного файла
`code_git/data/configs/conf_real_data_test_17_07_26-kmk-15-cam-lin-signal.txt`.
Он служит спецификацией для будущего преобразования новых параметров в формат,
который читает `code_git`.

На этапе первичного переноса вычислительный код и формат этого файла не
меняются. Все преобразования единиц должны выполняться только в адаптере и
проверяться регрессионными тестами.

## Служебные значения

Имя конфигурации и имя case не являются физическими параметрами. Они
формируются автоматически из безопасного имени эксперимента. Эти значения
определяют каталоги и имена файлов `code_git`, но не должны менять численный
результат.

| Поле legacy | Новый источник | Преобразование |
|---|---|---|
| `включена` | наличие `general.detectors.camera` | `да`/`нет` |
| `диагональ_передней_матрицы_(мм)` | `calibration_result.camera.matrix_diagonal_mm` | без преобразования |
| `количество_пикселей_длина_(шт)` | `general.detectors.camera.width_px` | без преобразования |
| `количество_пикселей_ширина_(шт)` | `general.detectors.camera.height_px` | без преобразования |
| `отступ_от_оптической_оси_(мкм)` | `calibration_result.camera.x_shift_m` | м ÷ 1e-6 |
| `отступ_от_оптической_оси_Y(мкм)` | `calibration_result.camera.y_shift_m` | м ÷ 1e-6 |

`camera.pixel_width_m` из результата калибровки напрямую в legacy-файл не
записывается. Геометрия моделируемой матрицы задаётся диагональю и количеством
пикселей.

Деление на `1e-6` выбрано намеренно. Legacy-калибровка сначала вычисляла
смещение в микрометрах, а затем сохраняла метры умножением на `1e-6`.
Обратное деление воспроизводит исходное двоичное значение; математически
эквивалентное умножение на `1e6` может изменить последний бит float.

## `Восстановление`

Эти параметры управляют внутренним тестовым восстановлением моделируемых
распределений, а не восстановлением реальных измерений.

| Поле legacy | Новый источник |
|---|---|
| `Тип` | `DarlQualityControl.restoration_type` |
| `Граница_маленьких_частиц(нм)` | `DarlQualityControl.small_particle_boundary_nm` |

Пока используются значения по умолчанию 1 и 300 нм. Они включаются в
фактически использованные параметры, хотя не делают `darl.yaml` громоздким.

## Параметры без прямого поля в legacy-конфигурации

Следующие значения входят в новые модели, но не записываются в данный файл:

- `general.instrument.focal_length_um` — используется другими этапами, но
  отсутствует в эталонном конфигурационном файле `code_git`;
- номинальные физические размеры пикселей из `general.yaml` — DARL получает
  скорректированную геометрию из результата калибровки;
- `calibration_result.camera.pixel_width_m` — геометрия камеры задаётся
  диагональю и размерами матрицы;
- `line_sensor.pixel_width_m`, `to_camera_coefficient`, `shift_m` и
  `peak_pixel` — потребляются этапом восстановления.

## Распределения

Распределения не являются частью текстового файла конфигурации. Исходный
`calc_darl.py` добавляет их в глобальный `STATE` после загрузки конфигурации.

Первичный автоматизированный запуск формирует их так:

1. встроенное контрольное распределение `pinhole_200`;
2. ожидаемые распределения из
   `input_parameters/measurements/<measurement>.yaml` в порядке имён
   измерений.

Параметры всех фактически добавленных распределений сохраняются в
`output/darl/used-parameters.yaml`.

## Контракт со следующим этапом

`output/darl/result.yaml` служит единственным машинным контрактом DARL для
этапа восстановления. В нём сохраняются включённые детекторы, тип сигнала
`signal`/`intensity`, пути к аппаратной матрице, классам частиц, файлам бинов,
фоновым сигналам и результатам распределений. `used-parameters.yaml` остаётся
полным снимком запуска для воспроизводимости, но следующий этап не должен
использовать его как конфигурационный вход.
