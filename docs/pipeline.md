# Оркестрация этапов обработки

`src/run.py` — основной пользовательский интерфейс проекта, а
`src/pipeline.py` — общий Python API оркестрации. Вычислительные реализации
остаются в `preprocessing.py`, `calc_darl.py` и `restore.py`.

## Подкоманды

```bash
python src/run.py calibration EXPERIMENT [COMMON_OPTIONS]
python src/run.py darl EXPERIMENT [COMMON_OPTIONS]
python src/run.py restore EXPERIMENT [RESTORE_OPTIONS] [COMMON_OPTIONS]
python src/run.py all EXPERIMENT [RESTORE_OPTIONS] [COMMON_OPTIONS]
```

Общие параметры:

```text
--force
--warnings-as-errors
--no-warnings
```

Параметры `restore` и `all`:

```text
--profile NAME
--measurement NAME
```

Селекторы можно повторять. Повтор одного имени удаляется с сохранением порядка.
Без селекторов восстановление выполняется для декартова произведения всех
профилей и всех измерений. Подкоманды `calibration` и `darl` не принимают
restore-селекторы.

## Общий Python API

`pipeline.py` предоставляет:

- `run_calibration_stage()`;
- `run_darl_stage()`;
- `run_restore_stage()`;
- `run_all_stages()`;
- `preflight_all()`.

Каждый отдельный этап возвращает неизменяемый `StageResult` с именем этапа,
созданными путями и полным `ValidationReport`. Ошибки передаются исключениями,
поэтому результат означает успешно опубликованный этап.

Прямые CLI этапов вызывают эти же функции. Они не запускают друг друга через
`subprocess`; дочерний процесс используется только там, где это уже является
частью адаптации legacy-вычислений калибровки или DARL.

## Полный процесс

`run_all_stages()` выполняет:

```text
preflight_all
→ run_calibration_stage
→ run_darl_stage
→ run_restore_stage
```

DARL загружает опубликованный результат только что выполненной калибровки, а
восстановление — опубликованные результаты калибровки и DARL. При исключении
следующие этапы не запускаются.

Селекторы влияют только на восстановление. Калибровка и текущий единый
legacy-расчёт DARL всегда выполняются для всего эксперимента.

## Предварительная проверка

До начала полного процесса проверяются:

- структура эксперимента и выбранные имена;
- схемы `general.yaml`, `calibration.yaml`, `darl.yaml` и выбранных restore
  profiles;
- согласованность детекторов исходных параметров;
- целевые каталоги калибровки, DARL и выбранных restore-пар.

Без `--force` существующий целевой каталог останавливает команду до запуска
калибровки. С `--force` существующий путь должен быть обычной директорией.
Фактическое архивирование остаётся ответственностью транзакции каждого этапа.

Предварительная проверка устраняет предсказуемые поздние конфликты, но не
заменяет независимую валидацию этапов. Например, DARL проверяется после
публикации нового результата калибровки, а восстановление — после публикации
нового результата DARL.

## Предупреждения

Каждый этап формирует отдельный `ValidationReport`:

- ошибки всегда останавливают этап;
- предупреждения в обычном режиме не останавливают вычисление;
- `--warnings-as-errors` останавливает этап до вычисления;
- `--no-warnings` скрывает подробности, но не меняет отчёт и его счётчики.

Для восстановления сначала валидируются все выбранные пары и только затем
начинается вычисление первой пары.

## Транзакционность

Калибровка, весь текущий DARL и каждая restore-пара публикуются отдельными
транзакциями. Временный каталог становится рабочим только после успешного
формирования и строгой проверки результата.

Полный процесс не образует единую транзакцию. Уже опубликованный успешный этап
не откатывается при ошибке следующего. Это сохраняет диагностические результаты
и позволяет продолжить работу отдельной подкомандой.

При `--force` архив повторяет структуру `output`:

```text
output/archive/calibration/<timestamp>/
output/archive/darl/<timestamp>/
output/archive/restore/<profile>/<measurement>/<timestamp>/
```

## Коды завершения CLI

```text
0 — команда успешно завершена;
1 — ошибка параметров, валидации, вычисления или публикации;
2 — ошибка структуры эксперимента, неизвестный селектор или синтаксис CLI.
```

## Интеграционная проверка

Полный процесс проверен командой:

```bash
python src/run.py all experiments/test_17_07_26_kmk_15 \
  --profile default --measurement kmk_15 --force
```

Подтверждены архивирование всех трёх результатов, строгая загрузка
`calibration/result.yaml`, `darl/result.yaml` и restore `result.yaml`, а также
побайтовое совпадение девяти контрольных файлов восстановления с legacy-
эталоном.
