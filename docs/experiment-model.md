# Варианты реализации модели эксперимента

## Публичный интерфейс

Остальные модули должны использовать публичные свойства и методы
`Experiment`, `Measurement` и `RestoreProfile` из `src/experiment.py`. Они не
должны самостоятельно перечислять измерения и профили или обращаться к
внутреннему состоянию этих классов.

Это позволяет менять внутреннюю реализацию модели без изменений в
калибровке, моделировании и восстановлении.

## Текущая реализация: ленивое чтение структуры

`Experiment.open()` проверяет корень эксперимента и `data/`. Методы
`measurements()` и `restore_profiles()` читают соответствующие директории при
каждом вызове и возвращают элементы в детерминированном порядке.

Преимущества:

- простая реализация;
- объект видит изменения файловой системы после `open()`;
- не требуется хранить внутренний снимок структуры.

Недостатки:

- файловая система сканируется повторно;
- часть ошибок может обнаружиться только при вызове конкретного метода;
- один объект может вернуть разные наборы элементов, если структура изменится
  во время работы.

Подход достаточен, пока структура эксперимента корректна и не изменяется во
время обработки.

## Альтернатива: снимок структуры при открытии

`Experiment.open()` может сразу проверить измерения и профили, создать
неизменяемые объекты `Measurement` и `RestoreProfile` и сохранить их во
внутренних коллекциях. Для защиты коллекций от изменения можно использовать
кортежи или `MappingProxyType`.

Преимущества:

- все статические ошибки обнаруживаются при открытии;
- структура сканируется один раз;
- один запуск работает с согласованным набором измерений и профилей;
- методы перечисления становятся проще.

Недостатки:

- реализация сложнее;
- изменения структуры после `open()` не видны до повторного открытия
  эксперимента;
- снимок фиксирует пути, но не предотвращает удаление файлов на диске.

## Условие совместимого рефакторинга

При переходе на снимок необходимо сохранить публичный интерфейс и поведение,
проверяемое тестами:

- абсолютные стандартные пути;
- сортированный порядок измерений и профилей;
- исключение `calibration` из измерений;
- отсутствие профилей при отсутствующей `restore_profiles/`;
- ошибки для неизвестных измерений и профилей;
- проверку существования обоих элементов в `restore_output_dir()`;
- отсутствие автоматического создания директорий моделью эксперимента.

Если существующие тесты продолжают проходить, внутреннюю реализацию можно
заменить без изменений в остальных модулях.
